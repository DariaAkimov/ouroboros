# HR AI-агент: Методология анализа

> **Область применения:** HR-данные руководящего корпуса (кадровый резерв и действующие руководители старших грейдов).
> **Версия документа:** 3.0
> **Дата:** июнь 2026
> **Назначение:** Методологическая и инженерная основа для AI-агента и для разработки его скиллов и тулов. Документ должен позволять отвечать на любой запрос о любом сотруднике — от простой справки до нетипичного («каверзного») стратегического вопроса первого лица.

> **О данных.** Рабочий датасет — синтетический и представляет собой выборку; в продуктивной системе сотрудников и записей существенно больше, а перечень функциональных блоков и территориальных банков может расширяться. **Поэтому ни одна формула, эвристика или порог в этой методологии не должны опираться на конкретное число сотрудников, блоков, ролей или строк.** Все методы формулируются масштабонезависимо: вместо «из 8 блоков» — «по всем блокам», вместо «среди 350 руководителей» — «по всей популяции запроса». Конкретные значения (списки блоков, ролей, наград и т. п.) приводятся как *наблюдаемые в текущей выборке примеры справочников*, которые агент должен достраивать из данных, а не как закрытые перечни.

## Что нового в версии 3.0 (резюме изменений к v2)

Версия 2.0 дала широкую таксономию вопросов (категории 1–20), сквозные принципы, этику и матрицу «вопрос → метод → источник». Эти части **сохранены** (см. разделы 1–5 ниже). Версия 3.0 **достраивает фундамент, без которого скиллы/тулы нельзя реализовать надёжно**, и исправляет ряд фактических ошибок о формате данных, которые ломали бы реализацию.

Добавлены новые опорные части (размещены **до** исходных разделов, потому что агент должен сначала освоить факты о данных):

- **Часть A. Авторитетный словарь данных** — пополевое описание всех листов: точные имена столбцов, типы, наблюдаемые домены значений, форматы, семантика пропусков, правила парсинга, особенности и «ловушки». Включает модель связывания листов и реестр форматов дат.
- **Часть B. Онтологии и контролируемые словари** — функциональные блоки (+синонимы и обработка несуществующих терминов вроде «Финансы»), география ЦА/ТБ, **лестница старшинства ролей**, маппинг англоязычных/неформальных названий должностей («chief data scientist», «CISO» и т. п.), таксономия наград, отраслей предыдущего работодателя, вузов, курсов, языков, интересов и активностей.
- **Часть C. Слои извлечения признаков из текста** — в т. ч. **«Реестр влияния» (Impact Ledger)**, извлекающий количественные результаты из поля «Ключевые достижения» (эконом-эффект, размер команды, SLA, сокращение цикла, число инициатив и т. д.), парсеры наград/образования/курсов/языков/активностей и извлечение «зон роста» из HTML-выводов паутинки.
- **Часть D. Каталог производных признаков (feature store)** — конкретный перечень вычисляемых признаков с источником и формулой: контракт, который реализуют тулы.
- **Часть E. Вычислительные примитивы и контракты тулов** — filter / aggregate / rank / parse / normalize / score / cohort-baseline / compare / correlate / trend / cluster, с указанием читаемых полей и форматов ввода-вывода.
- **Часть F. Когорты и базовые линии** — корректные группы сравнения и бенчмарки.
- **Часть G. Разрешение сущностей** — человек (ключ = табельный номер, омонимы), роль и блок (нечёткое сопоставление + протокол «нет точного совпадения»).
- **Часть H. Движок композиционных вопросов** — декомпозиция сложных/нетипичных запросов с разобранными примерами (включая «кто достоин занять место chief data scientist в блоке Финансы»).
- **Часть I. Многоисточниковая оценка пригодности (Fit/Readiness)** — усиление методологии 3.4 с резервным режимом «только профиль».
- **Часть J. Семантика коэффициента отработанного времени.**
- **Часть K. Контракт доказуемости и анти-галлюцинаций.**
- **Часть L. Этика, привязанная к фактическим полям.**

| # | Где в v2 | Было (неверно) | Стало (верно по данным) |
|---|---|---|---|

| К2 | 4.1.2 нормализация оценок | «D за результат / ценности» | **«Оценка за ценности» принимает только {B, C}** (значения D в ценностях отсутствуют). «Оценка за результат» — {B, C, D}. |
| К3 | 4.2.1 грейдовый контекст | «B за результат … на G18 ожидаемо» | По распределению **C — модальная оценка результата, B — выраженно выше целевого (меньшинство), D — редкий тревожный сигнал**. «B» трактуется как сильный сигнал, а не норма. |

| К6 | 4.1.5 «биполярные шкалы, нейтраль=5» | Сбертесты — биполярные пары | **Сбертесты — независимые униполярные шкалы 1–10.** Парные конструкты (напр. # ЧАСТЬ A. Авторитетный словарь данных

Это нормативное описание фактической схемы. Любая формула/порог в методологии должны ссылаться на **конкретные поля** из этого словаря; метод не имеет права молча зависеть от данных, которых в схеме нет.

## A.0 Модель связывания листов и нормализация ключа

- **Каноническая сущность** — сотрудник, идентифицируемый **табельным номером** (целое). Это сквозной ключ всех листов и единственный надёжный идентификатор (ФИО не уникально в продуктиве — см. часть G).
- **Имя ключевого столбца зависит от листа** и подлежит нормализации перед соединением:

| Лист | Имя столбца-ключа |
|---|---|
| профиль | `Табельный номер` |
| Паутинка (sberq и фокусные) / (сбертесты) / (опыт) / (выводы) | `табельный номер` |
| оценки за 5 лет / SberQ 1.0 / 3.0 / 4.0 / изменения грейдов за 5 лет | `табельный номер` |
| обучение за 2 года | `ТН` |
| цели 2026 | `Табельный Номер` |

  **Правило:** привести имя к канону `tn` (привести к нижнему регистру, схлопнуть пробелы, заменить алиас `ТН`→`tn`), привести значения к int, и только затем `join`.
- **Кардинальность.** профиль — один-к-одному с каждым сотрудником. Паутинки и SberQ — одна строка на сотрудника. оценки/обучение/цели/изменения грейдов — много строк на сотрудника.
- **Полнота связей.** Паутинки, SberQ, оценки, обучение, цели покрывают всю популяцию профиля. **Журнал изменений грейдов покрывает не всех** (у части сотрудников записей о смене грейда нет — это норма, а не ошибка; интерпретировать как «нет зафиксированных повышений в окне», не как нулевой потенциал).
- **Имена столбцов содержат «грязь»** (двойные пробелы, перевод строки внутри заголовка, разный регистр). Перед обращением к столбцам применять нормализацию заголовков: `strip`, схлопывание пробельных символов (`\s+`→` `). Пример: заголовок коэффициента нагрузки фактически содержит двойной пробел и перенос строки.

## A.1 Реестр листов (масштабонезависимо)

| Лист | Гранулярность | Назначение | Тип содержимого |
|---|---|---|---|
| **профиль** | 1 строка / сотрудник | Анкета: оргструктура, карьера, биография, образование, достижения, награды, режим, нагрузка | Структурный + полусвободный текст |
| **Паутинка (sberq и фокусные)** | 1 / сотрудник | Развёрнутые компетенции (детальные шкалы) | Числовой 1–10 |
| **Паутинка (сбертесты)** | 1 / сотрудник | Психологические склонности (независимые черты) | Числовой 1–10 |
| **Паутинка (опыт)** | 1 / сотрудник | Интегральные показатели опыта | Числовой ≈70–100 |
| **паутинка (выводы)** | 1 / сотрудник | Экспертные текстовые интерпретации (часть — HTML) | Текст / HTML |
| **обучение за 2 года** | много / сотрудник | Полный журнал пройденных курсов с датой завершения | Структурный |
| **оценки за 5 лет** | много / сотрудник | Оценки за ценности и результат по периодам | Структурный (категориальный) |
| **цели 2026** | много / сотрудник | Цели, КР, веса по кварталам и за год | Структурный + текст |
| **изменения грейдов за 5 лет** | много / сотрудник (не у всех) | Карьерные повышения с датой | Структурный |
| **SberQ 1.0 / 3.0 / 4.0** | 1 / сотрудник / версия | Компетенции по версиям модели + средний балл | Числовой 1–10 |

## A.2 Лист «профиль» — пополевой словарь

| Поле | Тип | Домен / формат (наблюдаемый) | Парсинг и производные | Особенности / ловушки |
|---|---|---|---|---|
| `Табельный номер` | int | Уникален | Канонический ключ `tn` | — |
| `Функциональный блок` | cat | Закрытый список блоков (см. B.1) | Нормализовать через онтологию блоков | Запросный блок может не совпадать буквально с данными (см. B.1: «Финансы» и пр.) |
| `ЦА\ТБ\ПЦП` | cat | `ПАО Сбербанк России (ЦА)` либо конкретный территориальный банк | Признаки `is_ca` (ЦА) / `tb_name` | Бэкслеши в имени столбца — экранировать |

| `Грейд` | int | Несколько старших грейдов (в выборке 16/17/18) | Контекст интерпретации (раздел 4.2.1) | Узкий диапазон → грейд слабо различает; опираться на роль+импакт |
| `Стаж в должности` | str | «N лет M месяцев» (рус. словоформы) | `parse_tenure`→годы (A.13/3.1) | Учитывать год/года/лет, месяц/месяца/месяцев; части могут отсутствовать |
| `Стаж в Сбере` | str | то же | то же; `role_to_sber_ratio = стаж_в_должности/стаж_в_Сбере` | — |
| `Ключевые достижения` | text | Свободный текст; предложения с встроенными числами | **Impact Ledger** (3.2): эконом-эффект (млн ₽/год), размер команды (чел.), SLA %, сокращение цикла (X→Y дней), число инициатив, предотвращённые потери (млн), релизы, рост в п.п./% | **Главный недооценённый источник.** Числа встроены в прозу; нужны устойчивые шаблоны извлечения |
| `Награды` | text | `Тип награды: YYYY-MM-DD`, через перевод строки | Парсер наград (3.3): тип, дата; `awards_count`, тиры престижа, свежесть | Полная ISO-дата; типы — см. B.5 |
| `Место работы до Сбера` | cat | Название компании | Маппинг в **отрасль** (B.6); `external_hire=true` если работодатель не внутренний | — |
| `Пол` | cat | `м` / `ж` | Только для **агрегатного D&I**; запрещён как фактор индивидуального решения (часть L) | — |

## A.8 Лист «оценки за 5 лет»

- Поля: ключ, `Год` (диапазон лет), `Квартал` ∈ {Q1, Q2, Q3, Q4, **Y**}, `Оценка за ценности` ∈ **{B, C}**, `Оценка за результат` ∈ **{B, C, D}** (исправления К2–К4).

- Производные: доля B по результату за окно, наличие любой D (флаг риска), стабильность (std кодов), наклон тренда по Y.
- Калибровка: поскольку C — модальная оценка результата, «доля B» — корректный индикатор устойчиво высокой результативности; единичная D — существенный сигнал, требующий контекста (реорганизация/кризис — раздел 4.5).

## A.9 Лист «цели 2026»

## B.2 География: ЦА и территориальные банки

- `ЦА\ТБ\ПЦП` различает **Центральный аппарат** (`ПАО Сбербанк России (ЦА)`) и **территориальные банки** (региональные). Список ТБ в данных — открытый и может пополняться; агент извлекает фактический перечень из данных, а не из захардкоженного списка.
- Признаки: `is_ca`, `tb_name`, регион. При сравнении ЦА↔ТБ всегда добавлять оговорку о разной природе задач (стратегия/системность vs клиентоцентричность/операционное лидерство — раздел 4.2.4).

## B.3 Лестница старшинства ролей (т. к. грейд узок)

Грейд принимает мало значений и плохо различает старшинство; **старшинство извлекается из наименования роли.** Ориентировочная лестница тиров (от старшего к младшему), которую агент достраивает по фактическим ролям:

| Тир | Маркеры в названии роли | Примеры из данных |
|---|---|---|
| T1 — верхнее руководство ТБ | «Председатель территориального банка», «Заместитель председателя ТБ», «Управляющий ТБ», «Исполнительный директор ТБ» | руководство региона |
| T2 — глава крупного контура | «Руководитель блока …», «Руководитель дивизиона …», «Директор департамента …» | «Руководитель блока крупных корпоративных клиентов», «Директор департамента AI-платформ» |

# ЧАСТЬ C. Слои извлечения признаков из текста

Это спецификации для тулов-парсеров. Каждый слой принимает сырое поле и возвращает структурированные записи + производные признаки. Все парсеры обязаны быть устойчивы к пропускам, разным формулировкам и разделителям (перевод строки, пробелы, `;`).

## C.1 Парсер стажа (`parse_tenure`)

Вход: «N лет M месяцев» в любых русских словоформах (`год/года/лет`, `месяц/месяца/месяцев`), части могут отсутствовать. Выход: `годы = years + months/12` (float). Применяется к «Стаж в должности» и «Стаж в Сбере». Производные: `tenure_role_years`, `tenure_sber_years`, `role_to_sber_ratio`, флаг «плато в должности» (большой стаж в должности **и** отсутствие записей о повышении в журнале грейдов — с оговоркой о неполноте журнала, A.10).

## C.2 Реестр влияния — Impact Ledger из «Ключевые достижения» (ключевой новый слой)

Поле «Ключевые достижения» — проза, в которую встроены количественные результаты. Слой извлекает их в структурированные записи и агрегирует. Это основа ответов о реальном вкладе и «достоин ли занять роль».

**Извлекаемые типы метрик (шаблоны — ориентир, не догма):**

| Метрика | Что значит | Шаблон (рус.) |
|---|---|---|
| Эконом-эффект | подтверждённый эффект, млн ₽/год | «экономический эффект **N** млн руб … в год» |
| Размер команды | численность сформированной команды | «команд… численностью **N** человек» |
| SLA | уровень выполнения SLA, % | «SLA на уровне **N**%» |
| Сокращение цикла | было→стало, дней | «сокращена с **X** до **Y** дней» |
| Число инициатив | выведено в пром. эксплуатацию | «выведено **N** инициатив» |
| Предотвращённые потери | млн ₽ | «предотвращённых потерь … **N** млн» |
| Релизы без замечаний | подготовлено релизов | «подготовлено **N** продуктовых релизов» |
| Рост (п.п.) | прирост в процентных пунктах | «на **N** п.п.» |
| Рост (%) | относительный прирост | «на **N**%» |

**Структура записи:** `{tn, metric_type, value, unit, direction (рост/снижение), raw_sentence}`. Несколько записей на сотрудника.

**Производные признаки влияния:**
- `impact_econ_total` = Σ эконом-эффектов (млн ₽/год); `impact_econ_max`.
- `impact_max_team` = максимальная численность команды.
- `impact_loss_prevented_total` (млн ₽).
- `impact_n_initiatives` = суммарно инициатив.
- `impact_has_sla99` = есть SLA ≥ 99%.
- `impact_cycle_best_reduction` = max(X−Y) по сокращению цикла; `impact_cycle_best_ratio` = max(1−Y/X).
- `impact_breadth` = число различных типов результатов (разнообразие вклада).

**Impact Score (нормированный, для ранжирования):** взвешенная сумма перцентильных рангов компонентов **внутри когорты** (часть F), например:
`Impact = 0.30·pr(econ_total) + 0.20·pr(max_team) + 0.15·pr(n_initiatives) + 0.15·pr(loss_prevented) + 0.10·pr(cycle_best_ratio) + 0.10·pr(impact_breadth)`.
Веса калибруются под функц. семейство (для технологий выше веса инициатив/циклов; для рисков — предотвращённых потерь; для КИБ — эконом-эффекта/кросс-продаж). **Перцентиль внутри когорты, а не абсолют**, потому что масштабы результатов различаются по функциям.

**Оговорки:** это самоописания, не аудит (A.14.4); язык достижений шаблонный — извлекать число, а не «красоту» фразы; отсутствие чисел в достижениях ≠ отсутствие вклада (возможен качественный результат).

## C.9 Сбертесты: независимые черты (исправление К6)

Каждую черту читать как самостоятельную величину 1–10. «Склонность к полюсу» парного конструкта — **только как явная разность** двух столбцов; не предполагать комплементарность/нейтраль=5. Любой вывод — с участием HRBP, как склонность, не способность (часть L).

## C.10 Нормализация «опыта» (исправление К5)

Перед агрегированием с 1–10 нормировать 4 показателя опыта min–max или по перцентилю внутри популяции, не делением на 100.

# ЧАСТЬ E. Вычислительные примитивы и контракты тулов

Скиллы/тулы строятся как композиция этих примитивов. Для каждого — назначение, читаемые поля и контракт ввода-вывода.

| Примитив | Назначение | Вход → Выход |
|---|---|---|
| `resolve_person` | разрешить человека в `tn` | имя/№/описание → `tn` или список кандидатов (часть G) |
| `resolve_role_block` | сопоставить роль/блок запроса с данными | текст → {block, role_family, allowed_roles} + допущения (B.4) |
| `filter` | отбор по предикатам над признаками | предикаты (поля D) → подмножество `tn` |
| `parse_text` | извлечение признаков из поля | сырое поле → структурированные записи (часть C) |
| `normalize` | приведение шкал/дат | значение+тип → нормализованное (A.12/A.13) |
| `aggregate` | сводные показатели по группе | группа+метрика → mean/median/доля/распределение |
| `cohort_baseline` | базовая линия и z/перцентиль | признак+когорта (часть F) → baseline, z, перцентиль |
| `rank` / `top_n` | ранжирование | признак/счёт+N → упорядоченный список с обоснованием |
| `score` | многофакторная оценка (Impact/Fit) | признаки+веса → балл с разложением вклада факторов |
| `compare` | сопоставление сущностей | список `tn`/групп+критерии → дельта-матрица |
| `correlate` | связь двух величин | две серии → r + интерпретация (с оговоркой «не причинность») |
| `trend` | динамика во времени | временной ряд → наклон/изменение (Q и Y раздельно) |
| `cluster` | сегментация по профилям | матрица признаков → кластеры/архетипы |
| `explain` | доказуемый вывод | результат+признаки → ответ с цитированием полей (часть K) |

Правила композиции: (1) сначала `resolve_*`, затем `filter`, затем `parse/normalize/score`, затем `rank/compare/aggregate`, затем `explain`; (2) каждый примитив декларирует читаемые поля — это позволяет проверить, что метод не зависит от отсутствующих данных; (3) при недостатке источников примитив возвращает частичный результат с пометкой (часть K), а не падает.

# ЧАСТЬ F. Когорты и базовые линии

Любое суждение «лучше/хуже/выдающийся/готов» бессмысленно без корректной группы сравнения.

- **Когорта по умолчанию для индивидуальной оценки:** одно функц. семейство ∧ соседний/тот же тир роли ∧ сопоставимый грейд. При нехватке размера — расширять по приоритету: семейство → блок → грейд → вся популяция, с пометкой о расширении.
- **Базовая линия:** медиана/перцентиль признака внутри когорты; для разнородных по масштабу метрик (импакт, опыт) — **перцентильный ранг**, не абсолют.
- **Выбросы:** z-оценка относительно когорты; |z|>1.5 — значимое отклонение (вверх — «звезда», вниз — «требует внимания»), всегда с контекстом роли/блока.
- **Минимальный порог:** не выдавать ранжирование/«лучшего», если когорта слишком мала для устойчивого вывода — сообщить об ограничении и дать описательный ответ.
- **ЦА vs ТБ и межблочные сравнения** — только с оговоркой о разной природе задач (4.2.4).

# ЧАСТЬ G. Разрешение сущностей

## G.1 Человек
1. **Ключ — табельный номер.** ФИО в продуктиве не уникально.
2. По имени: найти всех с совпадающим ФИО; если один — взять его `tn`; если несколько — **разрешать по дополнительным признакам запроса** (блок, роль, ТБ/ЦА, грейд); если всё ещё неоднозначно — **задать один уточняющий вопрос** с перечнем кандидатов (роль/блок), не угадывать.
3. По частичному имени/«фамилии» — то же; никогда не возвращать данные «похожего» человека без подтверждения.

## G.2 Роль и блок
Применять B.1/B.3/B.4 и протокол «нет совпадения» (B.4): сопоставить с фактическими значениями, при отсутствии — сообщить и предложить ближайшее/уточнить, фиксировать допущение. **Не выдумывать блок/роль, которых нет в данных.**

# ЧАСТЬ H. Движок композиционных (нетипичных) вопросов

Каверзный вопрос первого лица — обычно композиция фильтров, извлечённых признаков, оценки и ранжирования. Единый конвейер:

1. **Разбор намерения:** что является единицей ответа (человек / список / группа / да-нет / число / рекомендация) и какова цель решения.
2. **Разрешение сущностей** (часть G): люди, роли, блоки, отрасли, языки и т. п.; зафиксировать допущения.
3. **Построение предикатов** (фильтры над признаками D): жёсткие требования (например, `prior_sector∈{финтех}`, `has_degree`, `english_cefr≥C1`) и мягкие предпочтения (для скоринга).
4. **Вычисление признаков** через парсеры/нормализацию (части C/E).
5. **Скоринг/ранжирование** в нужной когорте (части F/I) с разложением вклада факторов.
6. **Доказуемый ответ** (часть K): цитирование полей+значений (+`tn`), уровень уверенности, допущения, чего не хватает.
7. **Оговорки/этика** (часть L): не использовать защищённые/лайфстайл-признаки как решающие; «человек в петле» для кадровых выводов.

### H.1 Разобранный пример (тот самый каверзный)
> **«Кто достоин занять место chief data scientist в блоке Финансы?»**

- **Разрешение:** блока «Финансы» в данных нет (B.1) → сообщить об этом. «chief data scientist» (B.4) → руководящие data/AI-роли. Ближайший по смыслу контур data/AI — блок «Технологическое развитие». Зафиксировать допущение: *«Трактую запрос как поиск преемника на старшую data/AI-руководящую роль (например, “Директор департамента AI-платформ” / “Управляющий директор по инженерии данных”); блок “Финансы” в данных отсутствует, использую блок “Технологическое развитие”; при необходимости уточните контур (например, финансово-аналитические роли есть в “Рисках” и “КИБ”).»*
- **Когорта/лонг-лист:** сотрудники Технологического блока в семействе data/AI на тир ниже целевой роли (B.3).
- **Скоринг (Fit, часть I)** с акцентом на data/AI: компетенции (sberq «данные/прогноз», «AI-помощник», «синтез/системность»), SberQ 4.0; **Impact** (инициативы AI/DataHub, эконом-эффект, размер команды, сокращение цикла из C.2); курсы AI/ML и элитные внешние (B.8); образование STEM/степень/публикации; устойчивость результата (доля B, без D); скорость роста; вовлечённость/фасилитация.
- **Ответ:** шорт-лист с обоснованием по каждому кандидату (цитирование конкретных достижений и баллов с `tn`), уровень готовности (часть I), допущения и оговорка «решение — за HR/руководителем».

### H.2 Другие классы нетипичных вопросов и как их собирать
- «Найди женщину-руководителя из бигтеха с PhD и опытом запуска AI с эффектом >X, готовую возглавить кибербез в регионе» → жёсткие фильтры (`Пол=ж` **только как часть явного запроса пользователя**, `prior_sector∈{бигтех}`, `has_degree`, Impact: эконом-эффект>X и AI-инициативы) + резолв блока «кибербез»→Кибербезопасность и географии→ТБ + Fit под кибербез-семейство + оговорка о неиспользовании пола как фактора при отсутствии явного требования.
- «Кого продвигать вместо ушедшего X» → resolve X → его роль/тир/блок → лонг-лист в семействе → Fit + readiness.
- «Где у нас единая точка отказа» → по каждой критичной роли: число сопоставимых преемников в семействе/блоке; роль с одним носителем + высоким стажем без записей о росте = риск (методология 3.6/3.7, с оговоркой A.10).
- «Дай неожиданный инсайт о резерве» → кластеризация по признакам D + поиск контринтуитивных паттернов (например, высокий импакт при средних компетенциях, или сильные внешние наймы без наград) — с пометкой «гипотеза, требует проверки».

# ЧАСТЬ I. Многоисточниковая оценка пригодности (Fit / Readiness)

Усиливает методологию 3.4. Если доступны паутинки/оценки/цели (как в полном датасете) — использовать их; **дополнительно** включать сигналы профиля; при отсутствии части источников у конкретного человека (например, свежий внешний найм) — переходить в **резервный режим «только профиль»**.

**Факторы Fit (веса — пресет по функц. семейству, калибруются):**

| Фактор | Источник | Комментарий |
|---|---|---|
| Соответствие компетенций целевой роли | sberq-паутинка, SberQ 4.0 | gap к профилю тира выше / медиане целевой роли |
| Доказанный вклад (Impact) | Ключевые достижения (C.2) | перцентиль импакта в когорте; акцент по семейству |
| Устойчивость результата | оценки за 5 лет | доля B, отсутствие D, стабильность, тренд по Y |
| Карьерная динамика | изменения грейдов | скорость роста (если есть записи; иначе — нейтрально + пометка) |
| Психологическое соответствие | сбертесты (независимые черты) | пороги под роль, с HRBP; полюс не «плохой» |
| Развитие под роль | курсы (C.5) | релевантные темы (AI/лидерство/риск/кибер…), свежесть |
| Зрелость/масштаб опыта | паутинка опыт | нормировано (C.10) |
| Образование/экспертиза | профиль | STEM/степень/публикации как вспомогательный сигнал |
| Языки/международность | профиль | где релевантно роли |
| Готовность/доступность | коэффициент нагрузки (часть J) | как контекст, не как штраф за низкое значение |

**Классификация готовности:** Ready Now / Ready 1–2 года / Ready 2–3 года / Не готов — по агрегированному Fit, **с разложением вклада факторов** и перечнем зон развития. 

**Резервный режим «только профиль»** (когда нет паутинок/оценок у человека): Fit считается из импакта, наград (престиж), образования/степени, языков, курсов (AI/лидерство), стажа/тира, отраслевой широты, вовлечённости/фасилитации, доступности — с явной пометкой «оценка по ограниченному набору источников; для полноты нужны паутинка/оценки».

**Обязательно:** Fit — рекомендация, не решение (часть L); ни один фактор сам по себе не дисквалифицирует; пол/интересы/престиж вуза не являются решающими факторами.

# ЧАСТЬ J. Семантика коэффициента отработанного времени

- Поле — доля фактически отработанного времени к нормативу за 2026 (наблюдаемо ≈ 0.85–0.99). Это **прокси доступности/нагрузки**, а не оценка эффективности.
- Полосы (ориентир, калибруется): ≥0.97 — высокая загрузка/почти полное присутствие (возможный сигнал перегрузки при прочих факторах); 0.90–0.97 — типично; <0.90 — пониженная отработка (**причины нейтральны:** отпуск, больничный, декрет, обучение, частичная занятость, ротация).
- **Фейрнес-правило:** низкий коэффициент **нельзя** использовать как самостоятельный негативный сигнал о человеке (результативности, лояльности, пригодности). Высокий — не «достижение». В кадровых выводах — только как контекст, и только в сочетании с другими факторами и с оговоркой о возможных причинах.

# ЧАСТЬ K. Контракт доказуемости и анти-галлюцинаций

Главный риск агента — выдать правдоподобное, но не подтверждённое данными утверждение. Обязательные правила вывода:

1. **Каждое фактическое утверждение привязано к источнику:** поле + значение (+ `tn`/роль для идентификации). Не приводить чисел, которых нет в данных или которые не извлечены парсером.
2. **Классификация запроса по достижимости:**
   - *в данных* — отвечать с цитированием;
   - *выводимо с допущениями* — выполнить и явно перечислить допущения (например, маппинг роли/блока, выбор когорты, веса Fit);
   - *требует внешних данных* (сравнение с конкурентом, рыночные бенчмарки, события вне системы) — честно сообщить ограничение и ответить на внутреннюю часть.
3. **«Нет данных» — допустимый ответ.** Если поле пустое или сущность не найдена — так и сказать; не достраивать факты. Помнить: пропуск в степенях/науке/наградах ≠ отсутствие факта.
4. **Уровень уверенности:** высокий (несколько независимых сигналов согласованы) / средний (один источник или есть расхождение) / низкий (косвенно/устаревше). Маркировать формулировкой.
5. **Никаких чисел «по памяти».** Все агрегаты/перцентили вычисляются на данных запроса; не опираться на конкретные значения из этой методологии (они иллюстративны).
6. **Тон — аналитический, не оценочный** (примеры в 4.4.4): сообщать показатель, базу сравнения и интерпретацию, а не ярлык.
7. **Воспроизводимость:** при сложном выводе кратко показать путь (фильтры → признаки → скоринг), чтобы человек мог проверить.

# ЧАСТЬ L. Этика, привязанная к фактическим полям

Дополняет раздел 4.5, привязывая принципы к конкретным полям схемы.

- **Пол** — допустим **только для агрегированной D&I-аналитики** (доли, паритет, динамика представленности). **Запрещён как фактор индивидуального кадрового решения** (отбор, Fit, ранжирование), **кроме** случая, когда пользователь явно и легитимно задаёт пол критерием запроса; и тогда — с оговоркой и без вторичного использования.
- **Интересы и лайфстайл** — **не являются** фактором кадровых решений о человеке; допустимы лишь для подбора менторства/нетворкинга/культурных программ, всегда с явной оговоркой.
- **Место работы до Сбера / престиж вуза** — вспомогательный контекст; не допускать дискриминации по происхождению/работодателю; не делать их решающими.
- **Сбертесты (психология)** — описывают склонности, не способности; ни один полюс не «плохой»; использовать только для соответствия роли **с участием HRBP**; не публиковать индивидуальные психопрофили неавторизованным лицам.
- **Коэффициент нагрузки** — см. часть J: не штрафовать за низкое значение.
- **Защищённые/чувствительные выводы** (риск ухода/выгорания, индивидуальные психоданные) — только авторизованным ролям и **только как рекомендация для человека** («человек в петле»); агент не инициирует кадровых действий.
- **Достоверность:** агент не верифицирует записи; формулировать как «по заявленным данным».
- **Масштабонезависимость и приватность:** не раскрывать перечни персональных данных сверх запроса; агрегаты предпочтительнее пофамильных списков, где это уместно.

## 2. Таксономия вопросов

Все вопросы, поступающие к HR AI-агенту, классифицируются по одной из **20 категорий** в зависимости от природы запроса, необходимых источников данных и типа аналитики. Первые 10 категорий (1–10) охватывают базовые аналитические операции: справки, профили, сравнения, оценку пригодности, анализ подразделений, кадровые решения, риски, обучение, тренды и стратегию. Категории 11–20 расширяют охват до демографического анализа, карьерных траекторий, командной химии, достижений, психологической совместимости, ротации, научной экспертизы, целеполагания и KPI, поведенческих паттернов, а также честной работы с ограничениями и неполными данными.

---

### Категория 1. Фактологические / справочные запросы

**Описание:** Прямое извлечение конкретных атрибутов одного сотрудника или группы без аналитической обработки. Ответ однозначен и определяется значением в таблице.

**Ключевые признаки:** содержит конкретное имя или табельный номер; запрашивается один атрибут или список атрибутов; нет слов «сравни», «оцени», «найди лучшего».

**Примеры вопросов:**
1. Какой грейд у Иванова Ивана Ивановича?
2. Сколько лет Петрова работает в Сбере?

### 3.1 Методология: Фактологические / справочные запросы

#### Источники данных
- Первичный: **профиль** (все атрибуты сотрудника)
- Вспомогательные: **обучение за 2 года**, **оценки за 5 лет**, **изменения грейдов**

#### Алгоритм решения

1. **Идентификация субъекта** — извлечь идентификатор из запроса: ФИО → Табельный номер (через профиль). Если несколько совпадений по ФИО — уточнить ТБ/блок.
2. **Определение запрашиваемого атрибута** — сопоставить ключевые слова запроса с именами полей источников.
3. **Извлечение значения** — прямое чтение ячейки или фильтрация по Табельному номеру.
4. **Нормализация** — при необходимости перевести сырые данные в читаемый формат (даты, стаж).
5. **Форматирование ответа** — краткий прямой ответ + источник (лист, поле).

#### Словарь синонимов запросов → поля

| Запрос (ключевые слова) | Лист | Поле |
|---|---|---|
| грейд, уровень | профиль | Грейд |
| стаж в Сбере, сколько лет в банке | профиль | Стаж в Сбере |
| стаж в должности | профиль | Стаж в должности |
| награды, поощрения | профиль | Награды |
| курсы, обучение | обучение за 2 года | Название курса, Дата завершения |
| оценка, результативность | оценки за 5 лет | Оценка за результат |
| режим работы | профиль | Режим работы |
| образование, вуз | профиль | Образование |
| языки | профиль | Знание языков |
| коэффициент, отработанное время | профиль | Коэффициент отработанного времени 2026 |

#### Интерпретационные правила
- Ответ должен быть точным и кратким.
- Если данные отсутствуют в таблице — явно сообщить «данные не заполнены», не интерполировать.
- При множественных значениях (несколько курсов, наград) — выводить список.

#### Пограничные случаи
- **Неоднозначность ФИО:** Если в базе два «Иванов Иван» — запросить ТБ или Табельный № для однозначной идентификации.
- **Устаревшие данные:** Стаж хранится как текст и не обновляется автоматически. Агент должен явно указать дату последнего обновления профиля.
- **Частичное совпадение:** Запрос «Петров» может дать несколько результатов — вернуть список совпадений.

#### Пример вычисления

> **Запрос:** «Сколько лет Козлова Анна Сергеевна работает в Сбере?»

1. Поиск по ФИО в профиль → Табельный № 789012, блок «Работа с персоналом», ТБ «ЦА».
2. Поле «Стаж в Сбере» = «13 лет 10 месяцев».
3. Нормализация: 13 + 10/12 = 13.83 лет.
4. **Ответ:** «Козлова Анна Сергеевна работает в Сбере 13 лет и 10 месяцев. Источник: лист "профиль".»

### 3.2 Методология: Анализ профиля сотрудника

#### Источники данных
- **профиль** — базовая биографика
- **Паутинка (sberq + фокусные)** — 39 компетенций
- **Паутинка (сбертесты)** — 50 психологических характеристик
- **Паутинка (опыт)** — 4 интегральных показателя
- **паутинка (выводы)** — интерпретационные тексты
- **оценки за 5 лет** — динамика результативности
- **SberQ 4.0** — актуальный структурированный профиль
- **цели 2026** — текущие задачи
- **обучение за 2 года** — развитие

#### Алгоритм решения

1. **Идентификация** — по ФИО/Табельному № получить все связанные записи из всех листов.
2. **Сбор блоков данных:** биографика, компетенции (все паутинки + SberQ), результативность (оценки), цели, траектория обучения.
3. **Нормализация шкал** — привести к единой базе для сравнения (см. раздел 4.1).
4. **Контекстуализация** — сравнить с медианой по грейду и роли (раздел 4.2).
5. **Выявление паттернов:**
   - Сильные стороны: компетенции ≥ 8 из 10
   - Зоны роста: компетенции ≤ 5 из 10
   - Динамика оценок (тренд: рост / стабильно / снижение)
6. **Интеграция текстовых выводов** — использовать паутинка (выводы) как основу нарратива.

```
  За счёт чего достигает результата
  Зоны развития + Рекомендации
```

#### Формула: Интегральный компетентностный индекс (ИКИ)

```
ИКИ = (Среднее SberQ 4.0) × 0.40
    + (Средняя паутинка sberq) × 0.30
    + (Средняя паутинка опыт / 10) × 0.20   // нормировка 1-100 → 1-10
    + (Нормированная оценка результат) × 0.10 // B=10, C=5, D=2.5
```

#### Шкала интерпретации ИКИ

| ИКИ | Интерпретация |
|---|---|
| 8.0–10.0 | Выдающийся — кандидат для succession G18, наставничества |
| 6.5–7.9 | Сильный — стабильный, с точечными зонами роста |
| 5.0–6.4 | Средний — необходим план развития, мониторинг |
| < 5.0 | Требует внимания — углублённая беседа с HR BP |

#### Пограничные случаи
- **Отсутствие данных по одной из паутинок:** использовать доступные блоки, скорректировать веса пропорционально, указать в ответе.
- **Текстовые выводы в HTML-формате:** очистить HTML-теги перед включением в ответ.
- **Расхождение числовых данных и текстовых выводов:** приоритет текстовым выводам как более контекстуальным.

### 3.3 Методология: Сравнительный анализ

#### Источники данных
- **SberQ 4.0** (основной для сравнения)
- **Паутинка (sberq + фокусные)**, **Паутинка (сбертесты)**
- **оценки за 5 лет**
- **профиль** (для контекстуализации)

#### Алгоритм решения

1. **Определение объектов сравнения** — список сотрудников или группа (блок/ТБ/грейд).
2. **Определение критериев сравнения** — из запроса извлечь, по каким атрибутам сравнивать.
3. **Нормализация** — привести все шкалы к единому диапазону.
4. **Агрегация для групп** — вычислить среднее, медиану, мин/макс, стандартное отклонение.
5. **Построение матрицы сравнения.**
6. **Выявление выбросов** (z-score > 1.5 или < -1.5).
7. **Формулировка выводов** — кто лучше/хуже и почему.

#### Формулы агрегации

```
# Для группы G из N сотрудников по компетенции K:
mean_K(G)   = Σ(score_K[i]) / N
median_K(G) = медиана всех score_K[i]
std_K(G)    = √(Σ(score_K[i] - mean_K)² / N)

# Z-score для выявления выдающихся:
z[i] = (score_K[i] - mean_K(G)) / std_K(G)
# z > 1.5  → значимо выше среднего
# z < -1.5 → значимо ниже среднего
```

#### Форматы вывода

**Попарное сравнение (2 человека):**

| Компетенция | Иванов | Петров | Разница | Лидер |
|---|---|---|---|---|
| Системное мышление | 8 | 6 | +2 | Иванов |
| Управление результатом | 7 | 9 | -2 | Петров |
| Жизнестойкость | 7 | 7 | 0 | — |
| Сотрудничество | 9 | 7 | +2 | Иванов |
| Развитие команды | 8 | 6 | +2 | Иванов |
| Клиентоцентричность | 7 | 8 | -1 | Петров |
| **Среднее** | **7.7** | **7.2** | **+0.5** | **Иванов** |

**Сравнение групп:**

| Блок | Среднее SberQ 4.0 | % B за результат | Топ-компетенция | Слабая компетенция |
|---|---|---|---|---|
| Кибербезопасность | 7.8 | 82% | Системное мышление | Клиентоцентричность |
| Технологическое развитие | 7.5 | 76% | Системное мышление | Развитие команды |
| Работа с персоналом | 7.2 | 79% | Сотрудничество | Управление результатом |

#### Интерпретационные правила
- Разница < 0.5 балла — статистически незначимая, не делать выводов о превосходстве.
- При сравнении групп разного размера нормировать на N.

### 3.4 Методология: Оценка пригодности к роли (succession, promotion)

#### Источники данных
- **профиль** — роль, грейд, стаж
- **SberQ 4.0** — компетенции
- **Паутинка (sberq + фокусные)** — расширенные компетенции
- **Паутинка (сбертесты)** — психологическое соответствие
- **оценки за 5 лет** — стабильность
- **изменения грейдов** — карьерная динамика

#### Алгоритм решения

1. **Определить целевую роль** и её требования (ключевые компетенции, минимальный стаж, психологический профиль).
2. **Сформировать лонг-лист** — сотрудники на 1 грейд ниже целевого.
3. **Вычислить Gap Score** для каждого кандидата:
   ```
   Gap_k = target_k - current_k  (для каждой ключевой компетенции k)
   Total_Gap = Σ|Gap_k| / N_компетенций
   ```
4. **Оценить стабильность** — стандартное отклонение оценок за 5 лет.
5. **Оценить тренд** — растущий тренд оценок = позитивный сигнал.
6. **Применить фильтры:** минимум по критическим компетенциям; отсутствие D-оценок за 2 года.
7. **Рассчитать Readiness Score** и присвоить статус готовности.

#### Матрица Readiness Score

| Критерий | Вес | Формула расчёта |
|---|---|---|
| Компетентностный gap | 40% | 1 - (Total_Gap / max_possible_gap) |
| Тренд оценок (3 года) | 20% | slope > 0 → 1.0; slope = 0 → 0.5; slope < 0 → 0 |
| Стабильность результатов | 15% | 1 - std(оценки за 5 лет) / 2 |
| Стаж (зрелость для роли) | 15% | min(стаж_в_Сбере / 5, 1.0) |
| Психологическое соответствие | 10% | Доля ключевых черт ≥ порога (из сбертесты) |

```
Readiness Score = Σ (Вес_k × Балл_k)
```

#### Классификация готовности

| Readiness Score | Статус | Рекомендуемое действие |
|---|---|---|
| 0.80–1.00 | Ready Now | Включить в succession plan немедленно |
| 0.65–0.79 | Ready in 1–2 года | Целенаправленное развитие, ротация |
| 0.50–0.64 | Ready in 2–3 года | Программа развития, менторинг |
| < 0.50 | Не готов | Вне succession для данной роли |

#### Психологические минимумы по типам ролей

| Тип роли | Обязательные характеристики (сбертесты) | Порог |
|---|---|---|
| Председатель ТБ | Экстраверсия, Публичность, Смелость, Командность | ≥ 7 |
| Руководитель кибербезопасности | Педантизм, Следование правилам, Рациональность | ≥ 7 |
| Руководитель цифровой трансформации | AI-партнёрство, Открытость новому, Смелость | ≥ 7 |
| Руководитель HR | Альтруизм, Эмоциональный интеллект, Открытость к ОС | ≥ 7 |

#### Пример вычисления

> **Запрос:** «Найди преемников для Председателя ТБ Сибирского банка»

Целевые компетенции: СМ ≥ 8, УР ≥ 8, Сотрудн. ≥ 8, Клиент. ≥ 7.

Кандидат Иванов: СМ=8, УР=9, Сотрудн.=8, Клиент.=8.

```
Total_Gap = (|8-8| + |8-9| + |8-8| + |7-8|) / 4 = 0.5
Компетентностный балл = 1 - (0.5 / 3) = 0.833

Тренд: +0.3/год → 1.0
Стабильность: std=0.4 → 1 - 0.4/2 = 0.8
Стаж: 11 лет → min(11/5, 1) = 1.0
Психология: Экстраверсия=8, Публичность=8 → 1.0

Readiness = 0.833×0.40 + 1.0×0.20 + 0.8×0.15 + 1.0×0.15 + 1.0×0.10
           = 0.333 + 0.200 + 0.120 + 0.150 + 0.100
           = 0.903  → Ready Now
```

### 3.9 Методология: Динамический / трендовый анализ

#### Источники данных
- **оценки за 5 лет** — квартальная динамика
- **SberQ 1.0 / 3.0 / 4.0** — эволюция компетенций
- **изменения грейдов за 5 лет** — карьерная динамика

#### Алгоритм решения

1. **Формирование временного ряда** — для субъекта (человек/группа) собрать данные по годам/кварталам.
2. **Расчёт тренда:**
   - Линейная регрессия (slope = угол наклона)
   - Скользящее среднее MA3 (3 квартала) для сглаживания
3. **Классификация тренда:**
   - slope > +0.1/квартал → Рост
   - slope в [-0.1; +0.1] → Стабильно
   - slope < -0.1/квартал → Снижение
4. **Выявление переломных точек** — кварталы с z > 2.
5. **Прогноз** — линейная экстраполяция с доверительным интервалом.

#### Таблица интерпретации трендов

| Паттерн | Оценки | Интерпретация | Рекомендованное действие |
|---|---|---|---|
| Устойчивый рост | B→B→B | Стабильно высокая результативность | Рассмотреть для succession |
| Рост после спада | D→C→B | Восстановление, адаптация | Поддержать, мониторить |
| Снижение | B→C→D | Ухудшение результативности | Срочная беседа HRBP |
| Волатильность | D→B→D→B | Нестабильность | Выявить триггеры |

#### Правило сравнения версий SberQ

Прямое числовое сравнение версий 1.0 → 3.0 → 4.0 некорректно без нормализации на когорту.
Рекомендуется сравнивать **перцентильный ранг** сотрудника внутри каждой версии:
```
Ранг_i(версия) = percentile(score_i, distribution_версии)
Delta_percentile = Ранг_i(v4.0) - Ранг_i(v3.0)
```

#### Пример прогнозирования

Оценки за результат (B=3, C=2, D=1): 2021:3, 2022:3, 2023:2, 2024:2, 2025:3.

Линейная регрессия: slope ≈ 0.0 → **Стабильно с временным провалом 2023–2024.**
Прогноз 2026: 2.8 ± 0.4 → «Вероятно оценка B, с небольшим риском C.»

### 3.11 Методология: Демографический и гендерный анализ (D&I)

#### Источники данных
- **профиль**: пол (бинарное поле), блок, ТБ/ЦА, грейд, роль, стаж в Сбере, стаж в должности, образование
- **изменения грейдов за 5 лет**: дата и направление изменения грейда — для анализа карьерного продвижения по полу
- **оценки за 5 лет**: оценка за результат и ценности — для сопоставления с демографией
- **Паутинка (sberq + фокусные)**: средний балл компетенций — для проверки систематических различий

#### Алгоритм решения
1. Определить единицу анализа: весь корпус vs блок vs ТБ/ЦА vs грейд vs роль.
2. Сегментировать данные по полу (или иному демографическому атрибуту).
3. Рассчитать базовые показатели: численность, доля, средний стаж, средний грейд, средняя оценка.
4. При наличии временного измерения — построить динамику по годам (используя оценки и изменения грейдов).
5. Применить статистические тесты при необходимости: χ² для распределений, t-тест для средних.
6. Идентифицировать блоки/ТБ с наибольшим отклонением от общей пропорции.
7. Сформулировать вывод: диспропорция подтверждена / не подтверждена, масштаб отклонения, возможные причины.

#### Формула / логика расчёта

```
Доля женщин в сегменте = N(женщины в сегменте) / N(все в сегменте) × 100%

Индекс паритета = Доля_женщины / Доля_мужчины
  → 1.0 = паритет; < 0.8 — значимый дисбаланс

Коэффициент карьерного продвижения по полу =
  N(повышений грейда у женщин) / N(женщин с ≥1 годом в системе)
  vs
  N(повышений грейда у мужчин) / N(мужчин с ≥1 годом в системе)
```

#### Интерпретационные правила
- Индекс паритета < 0.8 — сигнал потенциального структурного дисбаланса, требует внимания.
- Сравнивать следует внутри одного грейда или роли — межгрейдовые сравнения могут быть артефактом найма.
- Отсутствие данных о возрасте в системе ограничивает поколенческий анализ: допустимо использовать стаж в Сбере как прокси.
- Малые выборки (< 10 чел. в сегменте) требуют оговорки о низкой статистической мощности.

#### Пограничные случаи и оговорки
- В системе поле «пол» может отсутствовать или быть незаполненным для части сотрудников → агент сообщает о покрытии данных.
- При анализе динамики необходимо учитывать численность когорты в каждый год (входы/выходы сотрудников).
- Гендерный анализ не заменяет полноценный аудит D&I: зарплата, продвижение, наставничество выходят за рамки HR-системы.

#### Пример вычисления
Блок «Розничный бизнес», грейд 17: 48 руководителей, из них 14 женщин.
- Доля женщин = 14/48 = 29,2%
- По всему корпусу: например, 112 женщин из 350 в текущей выборке = 32% (значения иллюстративны)
- Индекс паритета блока = (14/48) / (34/48) = 0,29 / 0,71 = 0,41 → значимый дисбаланс
- За 5 лет в блоке: 6 повышений у мужчин из 34 (17,6%), 1 повышение у женщин из 14 (7,1%)
- Вывод: в блоке «Розничный бизнес» на грейде 17 зафиксирован двойной дисбаланс — представленность и карьерное продвижение женщин ниже общекорпоративного уровня.

### 3.12 Методология: Анализ карьерных траекторий

#### Источники данных
- **профиль**: место работы до Сбера, стаж в Сбере, стаж в должности, грейд, роль, блок, ТБ/ЦА
- **изменения грейдов за 5 лет**: дата, был грейд → стал грейд (для реконструкции внутренней траектории)
- **оценки за 5 лет**: результативность по годам — прокси успешности на каждом этапе
- **Паутинка (опыт)**: Широта контекстов, Масштаб влияния — для типологии «широкий vs глубокий»
- **Паутинка (выводы)**: текстовая интерпретация — подтверждение карьерного типа

#### Алгоритм решения
1. Для каждого сотрудника восстановить «карьерную цепочку»: внешний опыт → грейд входа → изменения грейдов → текущий грейд.
2. Кластеризовать по типу входа: внешний найм (указан работодатель до Сбера) vs внутренний рост (стаж в Сбере близок к общему опыту).
3. Для анализа скорости роста: рассчитать «лет до грейда X» как текущий год − год первого появления в системе на данном грейде.
4. Для анализа «откуда пришли»: нормализовать поле «место работы до Сбера» → отрасль / тип компании (банк, консалтинг, IT, госсектор, FMCG и т.д.).
5. Сопоставить кластеры с показателями оценок, компетенций (SberQ) и показателями Паутинки опыта.
6. Выявить статистически значимые паттерны; при n < 15 на кластер — сигнализировать о низкой достоверности.

#### Формула / логика расчёта

```
Скорость роста до грейда G =
  (Год достижения грейда G − Год прихода в Сбер) в годах

Индекс кросс-функциональности =
  N(уникальных блоков в истории сотрудника) / Max_блоков_в_системе
  → высокий индекс (> 0.3) = «широкий» профиль

Индекс внешнего опыта:
  0 = вырос полностью внутри Сбера
  1 = пришёл извне с >5 лет опыта в другой отрасли
```

#### Интерпретационные правила
- Руководители с высоким Индексом кросс-функциональности + высоким «Масштабом влияния» из Паутинки опыта — потенциально лучшие кандидаты на кросс-функциональные роли.
- Скорость роста < 2 лет до грейда 17 при среднем 3–4 года — признак «быстрой карьеры», требует проверки устойчивости результатов.
- «Внешние» руководители из консалтинга/IT показывают более высокие оценки за компетенции «Мышление» и «Предпринимательство» в среднем по выборке — это гипотеза для проверки, не постулат.

#### Пограничные случаи и оговорки
- Поле «место работы до Сбера» текстовое и нестандартизированное → возможны пропуски и разные написания одной компании.
- Некоторые сотрудники пришли на грейд 16, другие сразу на 17/18 — сравнивать скорость роста нужно только внутри когорт с одинаковым грейдом входа.
- Данные по изменениям грейдов охватывают только 5 лет — для длинных траекторий часть истории не видна.

#### Пример вычисления
Иванов А.А., грейд 18, стаж в Сбере 8 лет, место работы до Сбера: «McKinsey & Company».
- Тип входа: внешний (консалтинг)
- Изменения грейдов по данным: вошёл на 16, через 1,5 года → 17, через 3 года → 18
- Скорость роста: 4,5 года от грейда 16 до 18 (средняя по корпусу — 6,2 года)
- Индекс кросс-функциональности: работал в 3 блоках = 3/8 = 0,375 → «широкий» профиль
- Компетенции SberQ 4.0: Мышление 8,7, Предпринимательство 8,2 — выше среднего
- Вывод: типичный «быстрый внешний рекрут» с широкой траекторией и высокими когнитивными компетенциями.

### 3.13 Методология: Командная совместимость и подбор команды

#### Источники данных
- **Паутинка (sberq + фокусные)**: 39 компетенций (1–10) — основа для построения профилей и расчёта дополнительности
- **Паутинка (сбертесты)**: Когнитивный стиль, Мотивация (6 векторов), Карьерные мотиваторы — для психологической совместимости
- **Паутинка (опыт)**: Широта контекстов, Масштаб влияния, Жизненный интеллект — для баланса опытности
- **Паутинка (выводы)**: текстовые интерпретации зон роста и стиля управления
- **профиль**: грейд, роль, блок, стаж — контекстуальные фильтры

#### Алгоритм решения
1. Определить «якорный» профиль (лидер команды или задача): выделить его сильные стороны и пробелы.
2. Для каждого кандидата рассчитать «вектор дополнительности»: насколько он закрывает пробелы якоря.
3. Проверить отсутствие «слепых пятен команды»: зоны, где все члены команды имеют оценку < 5.
4. Рассчитать «когнитивное разнообразие»: дисперсия по шкалам Когнитивного стиля — высокая дисперсия = более креативная, но потенциально конфликтная команда.
5. Проверить мотивационную совместимость: команда с резко разными Карьерными мотиваторами требует особого управления.
6. Сформировать финальный рейтинг кандидатов с обоснованием выбора.

#### Формула / логика расчёта

```
Индекс дополнительности(A, B) =
  Σ max(0, ScoreB_i − ScoreA_i) по i ∈ [компетенции, где ScoreA_i < 6]
  → чем выше, тем больше B компенсирует пробелы A

Индекс когнитивного разнообразия команды =
  среднее(std по каждой когнитивной шкале) по членам команды
  → оптимальный диапазон: 2.0–3.5 (умеренное разнообразие)

Командный профиль компетенций =
  среднее по каждой из 39 компетенций для всех членов команды
  → визуализируется как «паутинка команды»
```

#### Интерпретационные правила
- Совместимость — не идентичность: высокое сходство профилей снижает конфликты, но и снижает разнообразие идей.
- «Слепые пятна» (компетенции < 5 у всех членов команды) критичнее, чем индивидуальные пробелы.
- При несовпадении мотивационных векторов > 3 из 6 — предупредить о возможных трениях в командной динамике.
- Данные Паутинки — самооценка + 360° + тестирование: уровень надёжности варьируется.

#### Пограничные случаи и оговорки
- Не все руководители имеют полный профиль Паутинки — неполные данные снижают точность анализа.
- Командная «химия» включает неформальные факторы (личная история, доверие), которые система не фиксирует.
- Агент не заменяет командный коучинг и живую динамику — рекомендации носят вероятностный характер.

#### Пример вычисления
Лидер команды: Петрова И.В., сильна в «Мышлении» (9,1) и «Предпринимательстве» (8,8), слаба в «Управлении командой» (4,2) и «Клиентоцентричности» (4,8).

Кандидаты: Сидоров (Упр. командой 8,5, Клиентоцентричность 7,9) → Индекс дополнительности = (8,5−4,2) + (7,9−4,8) = 7,4
Кузнецова (Упр. командой 6,1, Клиентоцентричность 8,3) → Индекс дополнительности = (6,1−4,2) + (8,3−4,8) = 5,4

Вывод: Сидоров — более сильный компенсатор для пробелов Петровой. Однако у обоих высокое «Предпринимательство» — рекомендуется добавить в команду «операционный» профиль.

### Категория 14. Анализ достижений, наград и признания

**Описание:** Запросы, связанные с формальными и неформальными достижениями руководителей: корпоративными наградами, упоминаниями в достижениях профиля, корпоративными активностями, публичным признанием. Категория помогает идентифицировать «звёзд» по нефинансовым показателям, понять, за что именно ценят людей в организации, и выявить систематические паттерны в том, кого и за что награждают.

**Ключевые признаки:** награды, достижения, признание, премия, лучший, победитель, корп. активность, награжден, отмечен, заслуги, вклад, общественное признание, корпоративные активности, волонтёр, наставник года.

**Примеры вопросов:**
1. У кого из грейда 18 больше всего корпоративных наград?
2. Какие достижения чаще всего упоминаются в профилях руководителей блока «Технологии»?
3. Есть ли корреляция между числом наград и оценкой за ценности?
4. Кто из руководителей активно участвует в корпоративных активностях (волонтёрство, наставничество, клубы)?
5. Сравни профили «многократно награждённых» и «ни разу не награждённых» — в чём разница по компетенциям и оценкам?
6. Построй «карту признания» по блокам: где награждают чаще, кого именно, и соответствует ли это показателям результативности?
7. Руководитель активно упоминается в достижениях, но его оценки за результат — «С». Это аномалия или нормальное явление?

### 3.14 Методология: Анализ достижений, наград и признания

#### Источники данных
- **профиль**: поля «достижения», «награды», «корп. активности» — основные источники
- **оценки за 5 лет**: оценка за ценности и результат — для корреляционного анализа
- **Паутинка (выводы)**: текстовые интерпретации — для качественного контекста
- **профиль**: грейд, блок, ТБ/ЦА, роль — для сегментации

#### Алгоритм решения
1. Парсинг текстовых полей «достижения» и «награды»: выделить упоминания конкретных премий, проектов, ролей.
2. Нормализовать типы наград: корпоративные (Сбер), отраслевые, государственные, неформальные.
3. Подсчитать количество упоминаний достижений и наград на сотрудника.
4. Построить рейтинг и сегментацию по блокам / грейдам.
5. Рассчитать корреляцию между числом достижений/наград и: (а) оценкой за ценности, (б) оценкой за результат, (в) средним баллом SberQ.
6. Выявить «аномалии»: высокое признание при низких оценках или наоборот.

#### Формула / логика расчёта

```
Индекс признания =
  N(упоминаний достижений) × 1 + N(наград) × 2 + N(корп. активностей) × 0.5
  → взвешенная сумма, нормированная на 100

Корреляция признания и результативности:
  r(Индекс признания, средняя оценка за результат за 5 лет)
  → r > 0.4 — умеренная связь; r < 0.2 — слабая / случайная
```

#### Интерпретационные правила
- Высокий Индекс признания при оценке «С» по результату может означать: признание за ценности/культуру, а не за KPI — это валидно.
- Поля «достижения» и «награды» заполняются неравномерно: отсутствие записей ≠ отсутствие достижений.
- Сравнение между блоками требует учёта культуры признания в блоке — одни блоки системно фиксируют больше, чем другие.

#### Пограничные случаи и оговорки
- Текстовые поля могут содержать неструктурированные данные, разные форматы дат, разные названия одной награды.
- Корп. активности (волонтёрство, клубы) — отдельная валюта признания, не эквивалентная бизнес-результатам.
- Агент не может верифицировать достоверность записей в профиле.

#### Пример вычисления
Руководитель Козлова М.Н.: 3 упоминания достижений, 2 корпоративные награды («Лучший наставник 2024», «Прорыв года 2023»), 4 корп. активности.
- Индекс признания = 3×1 + 2×2 + 4×0.5 = 9 (нормировано: 9/max × 100)
- Оценки за результат: 2022-С, 2023-D, 2024-С, 2025-С → среднее ≈ «С+»
- Интерпретация: высокое признание при оценке «С+» — паттерн «культурного чемпиона»: вероятно, ценится за вклад в атмосферу и развитие людей, а не за прямые KPI.

### 3.15 Методология: Психологическая совместимость и управление конфликтами

#### Источники данных
- **Паутинка (сбертесты)**: Характер (биполярные шкалы) — основной источник для оценки психологических паттернов; Ценности — для ценностной совместимости; AI-установки — для прогнозирования отношения к изменениям
- **Паутинка (выводы)**: текстовые интерпретации — качественный контекст
- **Паутинка (sberq + фокусные)**: «Самопознание», «Социальные навыки» — дополнительный контекст
- **профиль**: грейд, роль, блок — для контекстуализации

#### Алгоритм решения
1. Извлечь значения по всем биполярным шкалам характера для участников анализа.
2. Рассчитать «расстояние» между профилями по каждой шкале (|A_i − B_i|).
3. Идентифицировать «критические расхождения»: шкалы с расстоянием > 4 пунктов (на шкале 1–10).
4. Наложить ценностный профиль: выявить несовпадающие ценностные приоритеты.
5. Проверить AI-установки: рассогласование по отношению к технологиям — отдельный конфликтогенный фактор.
6. Сформулировать прогноз совместимости: высокая / умеренная / низкая + конкретные зоны риска.

#### Формула / логика расчёта

```
Индекс психологического расстояния(A, B) =
  √(Σ (A_i − B_i)²) по всем биполярным шкалам
  → < 5: высокая совместимость
  → 5–10: умеренная, возможны трения
  → > 10: значимые различия, требуют управления

Ценностный конфликт-score =
  N(ценностей с расхождением > 2 позиции в рейтинге) / N(всего ценностей)
  → > 0.5 — высокий потенциал ценностного конфликта
```

#### Интерпретационные правила
- Психологические данные — наиболее чувствительная категория в системе: интерпретировать осторожно.
- Расхождение на биполярных шкалах ≠ несовместимость: «дополняющие» различия могут быть продуктивны (напр., «структурированный» + «гибкий»).
- Критически опасная комбинация: оба высоко «доминантны» + противоположные ценности + нет пересечений в социальных навыках.
- AI-установки: руководители с «скептической» установкой в команде «энтузиастов» — потенциальный тормоз трансформации.

#### Пограничные случаи и оговорки
- Психологические профили могут быть устаревшими (дата прохождения тестирования не всегда актуальна).
- Агент не делает клинических оценок и не диагностирует личностные расстройства.
- Вывод «низкая совместимость» требует осторожного обсуждения — никогда не формулировать как приговор.

#### Пример вычисления
Руководители Александров и Борисова должны совместно вести стратегический проект.
Биполярные шкалы (выбор ключевых):
- Доминантность: А=8, Б=7 → разрыв 1 (норма)
- Структурированность: А=3, Б=9 → разрыв 6 (критический!)
- Эмпатия: А=4, Б=8 → разрыв 4 (умеренный)
- Ориентация на результат: А=9, Б=5 → разрыв 4 (умеренный)

Индекс психологического расстояния ≈ √(1+36+16+16+...) = значительный.
Ключевая зона риска: принципиально разный подход к планированию и процессу. Рекомендация: чётко разделить зоны ответственности, А отвечает за результат и стратегию, Б — за процесс и контроль качества.

### 3.16 Методология: Ротация, мобильность и управление перемещениями

#### Источники данных
- **профиль**: стаж в должности, стаж в Сбере, роль, блок, ТБ/ЦА, грейд
- **изменения грейдов за 5 лет**: история изменений (позволяет реконструировать смены позиций)
- **оценки за 5 лет**: динамика оценок — для детектирования «плато» и стагнации
- **Паутинка (sberq + фокусные)**: Обучаемость, Управление результатом — индикаторы готовности к новым вызовам
- **Паутинка (опыт)**: Широта контекстов — прямой показатель кросс-функциональной мобильности

#### Алгоритм решения
1. Рассчитать стаж на текущей позиции для каждого руководителя.
2. Идентифицировать «застрявших» (стаж > порогового значения, например 3–5 лет) с одновременным снижением оценок.
3. Построить «индекс мобильности» на основе числа смен ролей/блоков из доступной истории.
4. Сопоставить мобильность с траекторией оценок: растут, стагнируют или падают после ротаций?
5. Сформировать приоритетный список кандидатов на ротацию с обоснованием.
6. Для блокового анализа: сравнить среднюю внутреннюю мобильность и результативность блоков.

#### Формула / логика расчёта

```
Индекс мобильности =
  N(смен роли/блока за период наблюдения) / N(лет в системе)
  → > 0.5: высокая мобильность
  → 0.2–0.5: умеренная (нормальная)
  → < 0.2: низкая (риск стагнации или устойчивый специалист)

Индикатор «плато»:
  стаж на позиции > 3 лет
  + оценка за результат = «С» последние 2 года подряд
  + нет смен грейда
  → вероятное плато → кандидат на ротацию
```

#### Интерпретационные правила
- Долгий стаж на позиции ≠ стагнация: в экспертных ролях (учёная степень, узкоспециализированные направления) это норма.
- Высокая мобильность при падающих оценках — тревожный сигнал: частые переходы могут быть следствием неуспеха, а не развития.
- Ротация должна следовать за готовностью: Обучаемость < 5 + стресс-реакция по Паутинке → ротация может быть вредна.

#### Пограничные случаи и оговорки
- История ролей/блоков не всегда полностью восстанавливается из доступных данных — только 5 лет изменений грейдов.
- Ротация в другой ТБ/ЦА может иметь географическое измерение — не отражено в системе.
- Режим работы (удалёнка/офис) может ограничивать фактическую мобильность.

#### Пример вычисления
Смирнов В.П., грейд 16, стаж в должности: 4,5 года, стаж в Сбере: 6 лет. Оценки: 2022-С, 2023-С, 2024-С, 2025-С. Грейд не изменялся.
- Индикатор плато: ДА (стаж > 3 лет, оценка С, нет изменений грейда)
- Обучаемость по SberQ: 7,2 — высокая → готов к новым вызовам
- Широта контекстов: 35/100 — умеренная → есть пространство для расширения
- Рекомендация: включить в план горизонтальной ротации — перевод в смежный блок с новыми бизнес-задачами. Прогноз: рост оценок за результат в течение 1–2 кварталов после ротации (по аналогии с паттерном в базе данных).

### 3.17 Методология: Научная, экспертная и публичная деятельность

#### Источники данных
- **профиль**: учёные степени, научная деятельность, образование, курсы, достижения — основные поля
- **Паутинка (sberq + фокусные)**: «Мышление», «Обучаемость» — для сопоставления с академическим профилем
- **обучение за 2 года**: курсы с академической / профессиональной спецификой
- **оценки за 5 лет**: для корреляционного анализа «учёность–результативность»

#### Алгоритм решения
1. Извлечь все записи о учёных степенях и научной деятельности.
2. Классифицировать по типу: кандидат наук, доктор наук, PhD, MBA, иное.
3. Сопоставить с блоком, грейдом, ролью — построить тепловую карту академической насыщенности.
4. Для задач поиска экспертов: фильтровать по релевантной области + компетенции SberQ.
5. Рассчитать корреляцию «учёная степень → оценки по Мышлению и Обучаемости».
6. Для задачи формирования спикерского пула: наложить «Социальные навыки» + «Масштаб влияния» из Паутинки опыта.

#### Формула / логика расчёта

```
Экспертный индекс =
  (наличие учёной степени × 3) + (научная деятельность × 2)
  + (SberQ Мышление / 10) + (Масштаб влияния / 100)
  → нормировано на 10; > 7 → кандидат в экспертный пул

Академическая насыщенность блока =
  N(сотрудников со степенью) / N(всех в блоке) × 100%
```

#### Интерпретационные правила
- Учёная степень сама по себе не коррелирует однозначно с управленческой эффективностью — нужен анализ в связке с оценками.
- «Научная деятельность» в профиле — нестандартизированное поле: могут быть статьи, участие в советах, преподавание.
- Руководители с «двойной жизнью» (академическая + корпоративная) могут иметь ограничения по времени: проверить коэффициент отработанного времени 2026.

#### Пограничные случаи и оговорки
- Поле «научная деятельность» часто заполнено неполно или отсутствует.
- Академическая область степени может быть нерелевантна текущей роли.
- Агент не имеет доступа к публичным базам публикаций (Scopus, РИНЦ) — только данные профиля.

#### Пример вычисления
В блоке «Технологии» из 45 руководителей:
- 8 имеют степень кандидата наук (информатика, математика, физика)
- 2 — PhD (зарубежные университеты)
- 3 — ведут курсы в НИУ ВШЭ и МГУ
Академическая насыщенность: 13/45 = 28,9% — самый высокий показатель среди блоков.

### Категория 18. Анализ целей, KPI и управление результатом

### 3.18 Методология: Анализ целей, KPI и управление результатом

#### Источники данных
- **цели 2026**: название цели, описание, веса Q1–Q4 и Y, ключевой результат — основной источник
- **оценки за 5 лет**: исторические оценки за результат — для корреляции стиля целеполагания с итоговыми оценками
- **профиль**: грейд, роль, блок — для сегментации и нормирования
- **Паутинка (sberq + фокусные)**: «Управление результатом» — для контекста

#### Алгоритм решения
1. Агрегировать цели по сотруднику: N целей, суммарный вес, распределение по кварталам.
2. Проверить корректность весов **в рамках корректной модели весов (см. К7 и Часть A.9)**: веса нормированы **внутри каждой из тематических категорий цели** (в текущих данных таких категорий три — «Масштабирование направления», «Эффективность и надёжность», «Команда и экспертиза»), поэтому **суммарный вес по всем целям сотрудника-периода кратен числу категорий (порядка 300%, а не 100%)**. Проверять сумму нужно **по группам**, а не по всему набору целей разом.
3. Классифицировать качество ключевых результатов: наличие измеримого показателя (числа, %, даты) vs расплывчатая формулировка.
4. Проанализировать тематические паттерны: кластеризация целей по ключевым словам в названии.
5. Рассчитать «нагрузочный профиль»: N целей × средний вес → стандартизированный показатель.
6. Сопоставить с историческими оценками: влияет ли количество и структура целей на итоговую оценку?

#### Формула / логика расчёта

```
Индекс измеримости цели =
  N(целей с числовым KPI в ключевом результате) / N(всех целей) × 100%
  → > 70%: хорошее качество целеполагания
  → < 40%: риск субъективной оценки

Индекс квартальной концентрации =
  max(вес_Q) / среднее(вес_Q)
  → > 2.0: значимый перекос на один квартал

Проверка корректности весов (исправлено, см. К7):
  для каждой тематической категории цели: Σ(веса целей этой категории) ≈ 100% ± допуск
  суммарно по сотруднику: Σ(все веса) ≈ 100% × (число категорий)  [в текущих данных ≈ 300%]
  Флаг ставить ТОЛЬКО при отклонении ВНУТРИ категории; «не-100% по всем целям» — НЕ ошибка
```

#### Интерпретационные правила
- 5–8 целей на год — оптимальный диапазон для грейда 17–18.
- Более 10 целей при равномерных весах (~8–10%) — признак «распыления» ответственности.
- Перекос весов на Q4 (> 40%) может означать стратегические цели с длинным горизонтом или проблему планирования.
- Качество ключевого результата — прямой индикатор управленческой зрелости руководителя.

#### Пограничные случаи и оговорки
- Цели 2026 — данные текущего года: оценки будут только по завершении периода.
- Некоторые цели могут иметь нестандартную весовую логику (проект с одним ключевым дедлайном).
- Формулировки целей могут быть скрыты или обезличены в системе по соображениям конфиденциальности.

#### Пример вычисления
Руководитель Новикова С.А., грейд 17, 7 целей:
- Суммарный вес: 100% ✓
- Веса по кварталам: Q1=15%, Q2=20%, Q3=20%, Q4=45% → Индекс концентрации = 45/25 = 1,8 (умеренный перекос на Q4)
- Цели с числовым KPI: 5 из 7 = 71% → хорошее качество
- Типичные темы: клиентский NPS, выручка, развитие команды, цифровая трансформация
- Историческая оценка: D за результат в 2024 → гипотеза: высокое качество целеполагания коррелирует с высокой оценкой.

### 3.19 Методология: Поведенческие паттерны, интересы и лайфстайл-профиль

#### Источники данных
- **профиль**: интересы/хобби, языки, режим работы, корп. активности, коэффициент отработанного времени 2026 — основные поля
- **обучение за 2 года**: активность в обучении как индикатор поведенческого паттерна (когда учится, как часто)
- **оценки за 5 лет**: для корреляции режима работы с результативностью
- **Паутинка (сбертесты)**: Социальная ориентация, Мотивация — психологический контекст

#### Алгоритм решения
1. Парсинг текстовых полей «интересы/хобби»: нормализация, кластеризация по темам (спорт, искусство, технологии, путешествия, наука и т.д.).
2. Анализ языковой структуры: частотность языков, уровень (если указан), кластеры «международных» руководителей.
3. Сегментация по режиму работы: офис / гибрид / удалёнка — расчёт долей по блокам и грейдам.
4. Анализ коэффициента отработанного времени: аномалии (0, < 0.5, > 1.0), интерпретация причин.
5. Для задач нетворкинга: матрица пересечений интересов между руководителями.
6. Корреляционный анализ: режим работы × оценки за результат × компетенции.

#### Формула / логика расчёта

```
Индекс интересов-пересечений(A, B) =
  N(общих тем интересов) / N(уникальных тем у A∪B)
  → > 0.3: значимое совпадение → основа для нетворкинга/менторства

Коэффициент образовательной активности =
  N(завершённых курсов за 2 года) / 24 месяца
  → > 1 курса в месяц: высокоактивный learner
  → < 0.25: низкая активность в обучении

Аномалии коэффициента отработанного времени:
  = 0: отпуск без сохранения / декрет / болезнь / увольнение
  < 0.5: частичная занятость или длительное отсутствие
  > 1.0: переработки / нестандартный расчёт
```

#### Интерпретационные правила
- «Интересы» — нестандартизированное поле: одни заполняют подробно, другие оставляют пустым.
- Режим работы сам по себе не предсказывает результативность — важен контекст роли и задач.
- Коэффициент отработанного времени = 0 требует немедленного уточнения перед любыми кадровыми решениями.
- Многоязычность — не просто навык: коррелирует с Широтой контекстов и Жизненным интеллектом из Паутинки опыта.

#### Пограничные случаи и оговорки
- Данные о хобби и интересах не верифицируются — целиком со слов сотрудника.
- Языковой уровень может быть не указан: «знает английский» ≠ «может вести переговоры на английском».
- Гибридный режим работы может означать очень разные реальные практики (1 день в офисе vs 4 дня).

#### Пример вычисления
Запрос: «Найди руководителя-ментора для молодого топ-менеджера, интересующегося AI и имеющего международный опыт».
Фильтр 1 — языки: English + 1 иностранный → 47 кандидатов
Фильтр 2 — интересы/хобби содержат «AI», «технологии», «инновации» → 12 кандидатов
Фильтр 3 — место работы до Сбера = зарубежная компания ИЛИ научная деятельность = международная → 6 кандидатов
Фильтр 4 — Социальные навыки SberQ ≥ 7 + корп. активность «наставничество» → 3 финальных кандидата
Вывод: 3 потенциальных ментора с развёрнутыми профилями для выбора.

### 3.20 Методология: Неопределённость и ограничения агента

#### Источники данных
Данная категория активируется при **отсутствии** или **недостаточности** данных в системе, или при несоответствии запроса области работы агента. Агент опирается на:
- Полноту профиля (количество заполненных полей vs пустые)
- Покрытие данными временного периода (какие годы / кварталы есть в системе)
- Определение границ HR-системы (что в неё входит, что — нет)
- Список этически ограниченных запросов

#### Алгоритм решения
1. При получении запроса — проверить наличие и достаточность данных для ответа.
2. Если данных нет или недостаточно → идентифицировать тип ограничения (см. матрицу ниже).
3. Сформулировать ответ в соответствии с шаблоном для данного типа.
4. Предложить альтернативу: что агент может сделать вместо, или к кому обратиться.
5. Никогда не восполнять отсутствующие данные домыслами или внешними источниками без явного указания.

#### Интерпретационные правила
- **Шкала уверенности**: агент должен явно указывать уровень достоверности своих ответов, особенно при частичных данных. Рекомендуемая формулировка: «На основе [N из M] доступных полей», «с ограниченной достоверностью», «предварительно, требует уточнения».
- **Принцип минимального вреда**: при любой неопределённости предпочтительнее недосказать, чем ввести в заблуждение.
- **Прозрачность источника**: всегда указывать, из каких листов и полей получены данные, и какие поля отсутствуют.

#### Пограничные случаи и оговорки
- Неопределённость может быть **градуированной**: иногда данных «почти достаточно» — тогда агент даёт частичный ответ с явной оговоркой.
- Агент не должен «угадывать» отсутствующие данные на основе паттернов без явного предупреждения пользователя.
- Если неопределённость системная (например, поле «психологический профиль» пусто у > 30% сотрудников) — стоит упомянуть это как системную проблему качества данных.

#### Пример вычисления
Запрос: «Дай полный психологический портрет и прогноз карьерного роста для Васильева К.Д.»

Проверка данных:
- Профиль: ✓ (есть)
- Паутинка sberq: ✓ (частично — 6 из 39 компетенций)
- Паутинка сбертесты: ✗ (отсутствует)
- Паутинка опыт: ✓ (есть)
- Паутинка выводы: ✗ (отсутствует)
- Оценки: ✓ (2022–2025)

Ответ агента:
«Частичный анализ Васильева К.Д. возможен на основе: данных профиля, 6 компетенций SberQ (из 39), показателей опыта (Паутинка) и оценок за 4 года. [Частичный анализ здесь]

Ограничения: психологический профиль (сбертесты) и интерпретационные выводы Паутинки для этого сотрудника в системе отсутствуют — психологическая часть портрета и персонализированный прогноз карьеры не могут быть предоставлены с достаточной достоверностью. Рекомендую инициировать прохождение тестирования сотрудником для полноценного анализа.»

## 4. Сквозные принципы работы агента

### 4.1 Правила нормализации данных

#### 4.1.1 Парсинг стажа из текстового формата

```python
def parse_tenure(text: str) -> float:
    """
    Входные форматы:
      "4 года"            → 4.0
      "6 лет"             → 6.0
      "13 лет 10 месяцев" → 13.833
      "8 месяцев"         → 0.667
      "1 год 2 месяца"    → 1.167
    """
    import re
    years  = re.search(r'(\d+)\s*(?:год|года|лет)', text)
    months = re.search(r'(\d+)\s*месяц', text)
    y = int(years.group(1))  if years  else 0
    m = int(months.group(1)) if months else 0
    return y + m / 12
```

#### 4.1.2 Нормализация оценочных категорий

| Оценка | Тип | Числовое значение | Нормировка к 1–10 |
|---|---|---|---|
| B | Результат / Ценности | 3 | 10.0 |
| C | Результат / Ценности | 2 | 5.0 |
| D | Результат | 1 | 2.5 |

#### 4.1.3 Нормализация шкал для агрегации

| Исходная шкала | Целевая шкала | Формула |
|---|---|---|
| Паутинка sberq (1–10) | 0–1 | x / 10 |
| Паутинка сбертесты (1–10) | 0–1 | x / 10 |
| Паутинка опыт (1–100) | 0–1 | x / 100 |
| SberQ любая версия (1–10) | 0–1 | x / 10 |
| Оценка результат (D=1/C=2/B=3) | 0–1 | (x - 1) / 2 |

#### 4.1.4 Обработка дат наград

```
Форматы входных данных:
  "Почётная грамота 2023"          → year=2023, month=None
  "Серебряный знак, март 2022"     → year=2022, month=3
  "Благодарность ФБ 15.06.2024"   → year=2024, month=6, day=15

Правило: при неполных датах использовать только год для хронологического сравнения.
Подсчёт наград: count(список), без учёта порядка дат.
```

#### 4.1.5 Обработка шкал сбертестов

> **⚠️ Корректировка v3 (см. К6 и Часть C.9).** Эмпирически столбцы сбертестов — это **независимые однополюсные шкалы 1–10** (например, «Интроверсия» и «Экстраверсия» — *отдельные* столбцы со слабой корреляцией, а не два конца одной шкалы). Поэтому модель «5 = нейтральная середина одной биполярной оси» **неверна** и не должна закладываться в тулы. Каждый признак нормируется и интерпретируется самостоятельно (высокое значение = выраженность именно этого свойства). Текст ниже сохранён для исторической преемственности; при реализации руководствоваться Частью C.9.

Историческая (биполярная) трактовка — НЕ использовать как основу реализации:
- Значение 5 = нейтральная точка
- Значения 1–4 = ближе к левому полюсу
- Значения 6–10 = ближе к правому полюсу

**Критически важно:** оба полюса функциональны в зависимости от роли. Не интерпретировать ни один из полюсов как «плохо».

При агрегировании биполярных шкал в средние показатели — НЕ усреднять без контекста роли. Каждый полюс анализируется отдельно под требования конкретной позиции.

#### 4.1.6 Парсинг корпоративных активностей

Каждая запись вида «Название_активности, Дата»:
```json
{
  "type": "конференция | марафон | встреча | другое",
  "name": "...",
  "date": "YYYY-MM-DD"
}
```
Метрики: total_activities, activities_last_12m, activities_last_6m.

### 4.2 Правила контекстуализации

#### 4.2.1 Грейд как контекст интерпретации

| Параметр | G16 | G17 | G18 |

Один и тот же численный показатель **означает разное** в зависимости от грейда. Всегда указывать грейдовый контекст при сравнении.

#### 4.2.2 Роль как контекст компетенций

| Тип роли | Приоритетные компетенции |
|---|---|
| Председатель ТБ | Управление результатом, Сотрудничество, Клиентоцентричность |

| Директор по технологиям | Системное мышление, AI-партнёрство, Открытость новому |

| Инвестиционный бизнес | Управление результатом, Клиентоцентричность, Смелость |

#### 4.2.3 Функциональный блок как контекст

| Блок | Специфика интерпретации |
|---|---|
| Кибербезопасность | Педантизм, Следование правилам — позитивные характеристики |
| Технологическое развитие | AI-установка, Открытость новому — критически важны |
| Работа с персоналом | Социальные навыки, EI — доминирующие факторы |

#### 4.2.4 ЦА vs ТБ

- Сотрудники **ЦА**: более высокие ожидания по стратегическому мышлению и системности.
- Сотрудники **ТБ**: более высокие ожидания по клиентоцентричности и операционному лидерству.
- При любом сравнении ЦА и ТБ добавлять оговорку о различии функциональных задач.

### 4.3 Правила агрегации источников

#### 4.3.1 Иерархия достоверности источников

При конфликте данных из разных источников приоритет:
1. **паутинка (выводы)** — экспертная интерпретация (наивысший приоритет)
2. **SberQ 4.0** — актуальная стандартизированная оценка
3. **Паутинка (sberq + фокусные)** — детальная, 360°
4. **Паутинка (сбертесты)** — психологический контекст (не оценка компетенций)
5. **оценки за 5 лет** — результативность в практике
6. **Паутинка (опыт)** — контекст применения навыков

#### 4.3.2 Веса по умолчанию при агрегировании

| Источник | Вес | Обоснование |
|---|---|---|
| SberQ 4.0 | 35% | Актуальная, стандартизированная, сравнимая |
| Паутинка sberq | 25% | Детальная, 39 компетенций |
| Паутинка опыт | 20% | Независима от самооценки |
| Оценки за результат | 15% | Подтверждённая практикой эффективность |
| Паутинка сбертесты | 5% | Контекст, не оценка рабочих компетенций |

#### 4.3.3 Правило минимального порога данных

Агент **не формирует итоговую оценку**, если доступно менее 2 из 5 ключевых источников. При недостатке данных:
- Сообщить о недостаточности данных явно
- Сформулировать частичный вывод только по доступным данным
- Указать, какие данные нужны для полного анализа

#### 4.3.4 Временна́я актуальность данных

| Источник | Рекомендуемый срок актуальности | Действие при устаревании |
|---|---|---|
| профиль | 12 месяцев | Предупредить о возможной неактуальности |
| SberQ 4.0 | 18 месяцев | Использовать с флагом «требует обновления» |
| оценки за 5 лет | Релевантны всегда | — |
| Паутинка опыт | 24 месяца | Предупредить |

❌ «Эта группа самая слабая.»
✅ «Блок демонстрирует наименьший средний балл по "Клиентоцентричности" среди всех блоков (5.8 vs 7.1 в среднем по банку). Это системная зона роста, требующая внимания на уровне программы развития блока.»

### 4.5 Этические ограничения

#### 4.5.1 Недопустимые действия

| Действие | Обоснование запрета |
|---|---|
| Прямой вывод «уволить / не нанимать» | Решения о занятости — исключительная прерогатива человека |
| Публичное сравнение людей по психологическим характеристикам | Нарушение приватности, риск дискриминации |
| Вывод на основе единственного тревожного сигнала | Требуется конвергенция нескольких индикаторов |
| Анализ без учёта системного контекста (реорганизация, кризис) | Игнорирование внешних причин снижения результатов |
| Привязка психологических черт к этническому/гендерному профилю | Дискриминация |
| Раскрытие персональных данных неавторизованному лицу | ФЗ-152, корпоративные политики безопасности |
| Автоматическое инициирование изменений в HR-системах | Агент — аналитический помощник, не исполнитель решений |

#### 4.5.2 Ограничения при работе с психологическими данными

- Психологические данные описывают **склонности и предпочтения**, а не способности.
- Биполярные шкалы **не имеют «плохого» полюса** — интроверт может быть выдающимся лидером.
- Психологический профиль **не прогнозирует поведение** однозначно — только указывает на вероятные тенденции.
- Любой вывод на основе психологических данных должен содержать: «Для подтверждения рекомендуется беседа с HRBP.»

#### 4.5.3 Принцип «человек в петле»

Все выводы агента — **рекомендации**, требующие подтверждения HR BP или руководителя.
Высокорисковые выводы (выгорание, риск ухода) **всегда** передаются на рассмотрение человеку — агент не действует автономно.

#### 4.5.4 Управление доступом к данным

| Тип запроса | Уровень доступа |
|---|---|
| Агрегированные данные по блоку/грейду | Доступно HR-аналитикам |
| Полный профиль + числовые данные паутинок | Только HRBP |
| Психологические данные (сбертесты) конкретного человека | Только HRBP + руководитель с согласия сотрудника |
| Список рисков ухода/выгорания | Только HR-директор / HRBP |

## Приложение А: Глоссарий терминов

| Термин | Определение |
|---|---|
| **ИКИ** | Интегральный компетентностный индекс — взвешенная агрегация данных из нескольких источников, приведённая к шкале 0–10 |
| **Readiness Score** | Индекс готовности к следующей роли/грейду, рассчитываемый по пятифакторной модели |
| **Gap Analysis** | Анализ разрыва между текущим профилем компетенций и целевым (ролевым или грейдовым) |
| **Succession Coverage Rate** | Доля ключевых ролей в подразделении, для которых есть хотя бы один готовый преемник |
| **z-score** | Стандартизированная оценка отклонения значения от среднего по группе в единицах стандартного отклонения |
| **Шкала сбертеста** | Независимая однополюсная шкала 1–10: высокое значение = выраженность данного свойства. Парные свойства (например, «Интроверсия»/«Экстраверсия») — это *отдельные* столбцы, а не концы одной оси; модель «нейтраль = 5» не применяется (см. К6, Часть C.9) |
| **HRBP** | HR Business Partner — HR-менеджер, закреплённый за подразделением |
| **Коэффициент отработанного времени** | Отношение фактически отработанного времени к нормативному за период 2026 года (~0.93–1.0) |
| **Лонг-лист** | Расширенный список кандидатов до применения детальных критериев отбора |
| **Шорт-лист** | Финальный список кандидатов после всех фильтров |
| **SberQ** | Корпоративная модель оценки компетенций Сбербанка (версии 1.0, 3.0, 4.0) |
| **Паутинка** | Инструмент многомерной оценки руководителей в Сбербанке (несколько модулей) |
| **G16 / G17 / G18** | Грейды руководителей, G18 — наивысший уровень в данной выборке |
| **ЦА** | Центральный аппарат (Головной офис ПАО Сбербанк) |
| **ТБ** | Территориальный банк (региональный) |
| **MA3** | Moving Average 3 — скользящее среднее по 3 периодам для сглаживания временных рядов |
| **KR** | Key Result — ключевой результат цели (в терминологии OKR) |
